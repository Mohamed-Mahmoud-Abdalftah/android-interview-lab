# UI-Q005 — Complete model answer

**Spoken answer:** “I can claim the tested policy distinguishes stable row ID from content and detaches a list container. I cannot claim DiffUtil animations, adapter notifications, Fragment cleanup or accessibility work, because no AndroidX component ran.”

<p dir="rtl" lang="ar">اختبار JVM تثبت دوال policy فقط. ما تقولش RecyclerView اشتغلت ولا memory leak اتصلحت قبل Android integration. اذكر مصادر AndroidX وخطة اختبار فعلية.</p>

**Mechanics:** Unit-level domain policy and platform integration are different evidence. A real adapter test should exercise DiffUtil ItemCallback, submission order, holder binding, Fragment view recreation and row accessibility. [RecyclerView guide](https://developer.android.com/develop/ui/views/layout/recyclerview), [ListAdapter API](https://developer.android.com/reference/kotlin/androidx/recyclerview/widget/ListAdapter) and [view binding](https://developer.android.com/topic/libraries/view-binding) were checked 2026-10-10.

**Common wrong answer:** “The row comparator passed, so our screen is regression-free.” That overstates the evidence.

**Follow-up 1:** What is the next most useful integration test? Submit a list with a changed title under the same ID and assert the rendered holder updates; then test Fragment view recreation.

**Follow-up 2:** What should be reviewed for RTL and accessibility? Text direction, focus order, content descriptions and row semantics on the actual device or emulator.

**Rubric for self-review:** Separate item identity from displayed content, state the list ownership contract, match view work to view lifecycle, and distinguish JVM policy proof from Android integration. This is visible practice, not a scored assessment.
