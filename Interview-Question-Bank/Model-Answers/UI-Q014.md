# UI-Q014 — Complete model answer

## الإجابة المختصرة

**Spoken answer:** “Collect UI state only while the chosen lifecycle is active and use the correct owner.”

<p dir="rtl" lang="ar"><strong>الخلاصة بالمصري:</strong> effect identity تحددها keys، التسجيل له cleanup مطابق، والcallback الحديثة تُقرأ من غير restart غير مطلوب.</p>

## افهم السؤال قبل ما تجاوب

<p dir="rtl" lang="ar"><strong>المحاور بيديك الحالة دي:</strong> <bdi dir="ltr">A Fragment or Compose screen collects a hot Flow while not visible. Compare repeatOnLifecycle and collectAsStateWithLifecycle, including cancellation and upstream sharing.</bdi></p>

<p dir="rtl" lang="ar"><strong>تحت الغطا في Lifecycle-aware collection:</strong> LaunchedEffect تربط coroutine بمجموعة keys؛ تغير key يلغي القديمة ويبدأ جديدة. DisposableEffect تربط register/unregister بنفس lifetime. rememberUpdatedState تغير القيمة المقروءة داخل effect طويلة من غير restart.</p>

<p dir="rtl" lang="ar"><strong>إيه اللي لازم يظهر في إجابتك؟</strong> حدّد الـowner، امشِ في الـexecution order، سمّي الـfailure اللي السؤال كاشفها، وبعدها اربط القرار بـtrade-off واختبار يثبت السلوك.</p>

## القرار العملي

<p dir="rtl" lang="ar">بالنسبة لـLifecycle-aware collection: اختار keys تمثل lifetime الحقيقي، استخدم DisposableEffect للregister/unregister وrememberUpdatedState للقيمة الحديثة داخل effect طويلة.</p>

## الـfailure والـwrong answer

**Common wrong answer:** “Use Unit as every effect key and read whatever callback was captured initially.”

<p dir="rtl" lang="ar">في <strong>Lifecycle-aware collection</strong> المشكلة في الإجابة دي إنها تكسر الـinvariant الأساسية: effect identity تحددها keys، التسجيل له cleanup مطابق، والcallback الحديثة تُقرأ من غير restart غير مطلوب. النتيجة ممكن تبان سليمة في الـhappy path، وبعد race أوrecreation أوfailure boundary تظهر المشكلة الحقيقية.</p>

## الـtrade-off

<p dir="rtl" lang="ar">في Lifecycle-aware collection: event handler عادية أفضل لو مفيش lifecycle side effect؛ متستخدمش Effect API لنقل pure calculation.</p>

## الاختبار اللي يثبت الإجابة

<p dir="rtl" lang="ar">لاختبار Lifecycle-aware collection: غيّر key وcallback وlifecycle بترتيب متحكم، واثبت start/cancel/cleanup مرة واحدة وعدم callback على owner متوقفة.</p>
