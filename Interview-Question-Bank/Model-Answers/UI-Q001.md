# UI-Q001 — Complete model answer

**Spoken answer:** “The LayoutManager positions and recycles the visible layout, the Adapter creates and binds ViewHolders, and each ViewHolder holds row views. The adapter’s DiffUtil callback defines logical item identity and visible content equality.”

<p dir="rtl" lang="ar">LayoutManager ترتب rows، Adapter تنشئ وتربط ViewHolder، وViewHolder تمسك views للـ row. سياسة identity/content في DiffUtil callback التي يختارها adapter.</p>

**Mechanics:** The official RecyclerView guide describes adapter creation/binding and layout management. A ListAdapter wraps diff calculation, but the app supplies a correct ItemCallback for its domain. [RecyclerView guide](https://developer.android.com/develop/ui/views/layout/recyclerview), [ListAdapter API](https://developer.android.com/reference/kotlin/androidx/recyclerview/widget/ListAdapter) and [view binding](https://developer.android.com/topic/libraries/view-binding) were checked 2026-10-10.

**Common wrong answer:** “ViewHolder decides whether two notes are the same record.” A holder can be reused for many items and does not own domain identity.

**Follow-up 1:** When is onBindViewHolder called? When RecyclerView needs a holder associated with a dataset item; binding must render all relevant state for reuse.

**Follow-up 2:** Can a holder keep stale click data? Yes if a listener captures an old position or value; use current binding data and handle position changes carefully.

**Rubric for self-review:** Separate item identity from displayed content, state the list ownership contract, match view work to view lifecycle, and distinguish JVM policy proof from Android integration. This is visible practice, not a scored assessment.
