# UI-Q013 — Complete model answer

## الإجابة المختصرة

**Spoken answer:** “Keep a long-lived effect while reading the latest callback or value without an unnecessary restart.”

<p dir="rtl" lang="ar"><strong>الخلاصة بالمصري:</strong> effect identity تحددها keys، التسجيل له cleanup مطابق، والcallback الحديثة تُقرأ من غير restart غير مطلوب.</p>

## افهم السؤال قبل ما تجاوب

<p dir="rtl" lang="ar"><strong>المحاور بيديك الحالة دي:</strong> <bdi dir="ltr">A long-lived effect should keep its timer but invoke the latest onTimeout lambda. Explain why keying on the lambda restarts too much and how rememberUpdatedState changes the capture.</bdi></p>

<p dir="rtl" lang="ar"><strong>تحت الغطا في rememberUpdatedState:</strong> LaunchedEffect تربط coroutine بمجموعة keys؛ تغير key يلغي القديمة ويبدأ جديدة. DisposableEffect تربط register/unregister بنفس lifetime. rememberUpdatedState تغير القيمة المقروءة داخل effect طويلة من غير restart.</p>

<p dir="rtl" lang="ar"><strong>إيه اللي لازم يظهر في إجابتك؟</strong> حدّد الـowner، امشِ في الـexecution order، سمّي الـfailure اللي السؤال كاشفها، وبعدها اربط القرار بـtrade-off واختبار يثبت السلوك.</p>

## القرار العملي

<p dir="rtl" lang="ar">بالنسبة لـrememberUpdatedState: اختار keys تمثل lifetime الحقيقي، استخدم DisposableEffect للregister/unregister وrememberUpdatedState للقيمة الحديثة داخل effect طويلة.</p>

## الـfailure والـwrong answer

**Common wrong answer:** “Use Unit as every effect key and read whatever callback was captured initially.”

<p dir="rtl" lang="ar">في <strong>rememberUpdatedState</strong> المشكلة في الإجابة دي إنها تكسر الـinvariant الأساسية: effect identity تحددها keys، التسجيل له cleanup مطابق، والcallback الحديثة تُقرأ من غير restart غير مطلوب. النتيجة ممكن تبان سليمة في الـhappy path، وبعد race أوrecreation أوfailure boundary تظهر المشكلة الحقيقية.</p>

## الـtrade-off

<p dir="rtl" lang="ar">في rememberUpdatedState: event handler عادية أفضل لو مفيش lifecycle side effect؛ متستخدمش Effect API لنقل pure calculation.</p>

## الاختبار اللي يثبت الإجابة

<p dir="rtl" lang="ar">لاختبار rememberUpdatedState: غيّر key وcallback وlifecycle بترتيب متحكم، واثبت start/cancel/cleanup مرة واحدة وعدم callback على owner متوقفة.</p>
