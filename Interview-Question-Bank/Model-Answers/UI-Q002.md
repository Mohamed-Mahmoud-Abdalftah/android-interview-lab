# UI-Q002 — Complete model answer

**Spoken answer:** “The logical item is the same, so areItemsTheSame returns true. The displayed title changed, so areContentsTheSame returns false and the row should be rebound.”

<p dir="rtl" lang="ar">ID ثابتة تعني نفس note، لكن title المعروضة اتغيرت. لو تقارن ID بس في المحتوى هتفوت update. ولو تقارن title للهوية هتعامل update كأنه item جديدة.</p>

**Mechanics:** The domain key identifies a row across updates; content comparison checks fields relevant to rendering. The pure JVM NoteRow test exercises this distinction without executing DiffUtil itself. [RecyclerView guide](https://developer.android.com/develop/ui/views/layout/recyclerview), [ListAdapter API](https://developer.android.com/reference/kotlin/androidx/recyclerview/widget/ListAdapter) and [view binding](https://developer.android.com/topic/libraries/view-binding) were checked 2026-10-10.

**Common wrong answer:** “Both methods return true because ID is unchanged.” That misses a visible content update.

**Follow-up 1:** What if two tenants both use note ID n-1? The true identity may need tenantId plus noteId; choose a key unique in the adapter’s domain.

**Follow-up 2:** Must content equality include every backend field? Only fields that affect this row’s presentation or behavior under the adapter contract.

**Rubric for self-review:** Separate item identity from displayed content, state the list ownership contract, match view work to view lifecycle, and distinguish JVM policy proof from Android integration. This is visible practice, not a scored assessment.
