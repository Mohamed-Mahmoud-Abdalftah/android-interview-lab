# UI-Q025 — Complete model answer

## الإجابة المختصرة

**Spoken answer:** “Measure frame timing and expensive phases on representative release builds before optimizing.”

<p dir="rtl" lang="ar"><strong>الخلاصة بالمصري:</strong> تحسين UI لازم يقلل frame time في stage محددة على release-like build مع الحفاظ على pixels وsemantics وinteraction؛ recomposition count وحدها ليست metric نجاح.</p>

## افهم السؤال قبل ما تجاوب

<p dir="rtl" lang="ar"><strong>المحاور بيديك الحالة دي:</strong> <bdi dir="ltr">A LazyColumn drops frames during fast scroll. Design a trace-driven investigation across item identity, composition work, measure/layout, image loading, and allocation.</bdi></p>

<p dir="rtl" lang="ar"><strong>تحت الغطا في UI performance evidence:</strong> تحسين UI لازم يقلل frame time في stage محددة على release-like build مع الحفاظ على pixels وsemantics وinteraction؛ recomposition count وحدها ليست metric نجاح. حدد journey وslow-frame percentile، استخدم Perfetto أوMacrobenchmark لتحديد composition/measure/draw/GC/I/O، أصلح أكبر slice، ثم أعد القياس بنفس الظروف.</p>

<p dir="rtl" lang="ar"><strong>إيه اللي لازم يظهر في إجابتك؟</strong> حدّد الـowner، امشِ في الـexecution order، سمّي الـfailure اللي السؤال كاشفها، وبعدها اربط القرار بـtrade-off واختبار يثبت السلوك.</p>

## القرار العملي

<p dir="rtl" lang="ar">بالنسبة لـUI performance evidence: حدد journey وslow-frame percentile، استخدم Perfetto أوMacrobenchmark لتحديد composition/measure/draw/GC/I/O، أصلح أكبر slice، ثم أعد القياس بنفس الظروف.</p>

## الـfailure والـwrong answer

**Common wrong answer:** “A lower recomposition count automatically proves that scrolling is faster.”

<p dir="rtl" lang="ar">في <strong>UI performance evidence</strong> المشكلة في الإجابة دي إنها تكسر الـinvariant الأساسية: تحسين UI لازم يقلل frame time في stage محددة على release-like build مع الحفاظ على pixels وsemantics وinteraction؛ recomposition count وحدها ليست metric نجاح. النتيجة ممكن تبان سليمة في الـhappy path، وبعد race أوrecreation أوfailure boundary تظهر المشكلة الحقيقية.</p>

## الـtrade-off

<p dir="rtl" lang="ar">في UI performance evidence: recomposition رخيصة لا تحتاج منع؛ optimization أعقد تُرفض لو لا تحسن user metric أوتكسر readability/accessibility.</p>

## الاختبار اللي يثبت الإجابة

<p dir="rtl" lang="ar">لاختبار UI performance evidence: شغّل benchmark بعد warm-up على نفس device class وcompilation mode، قارن P50/P95/P99 وframe overruns، وأعد semantics وvisual regression بعد التغيير.</p>
