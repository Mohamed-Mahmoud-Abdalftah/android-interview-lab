# UI-Q007 — Complete model answer

## الإجابة المختصرة

**Spoken answer:** “Hoist state as value plus events to the lowest common owner that needs coordination.”

<p dir="rtl" lang="ar"><strong>الخلاصة بالمصري:</strong> Compose تقرأ observable immutable state، owner واحدة تستقبل events، وأي stability contract صادق عن كل observable field.</p>

## افهم السؤال قبل ما تجاوب

<p dir="rtl" lang="ar"><strong>المحاور بيديك الحالة دي:</strong> <bdi dir="ltr">A reusable date picker owns selection, validation, and navigation internally. Decide what state and events to hoist while keeping transient UI details local.</bdi></p>

<p dir="rtl" lang="ar"><strong>تحت الغطا في State hoisting:</strong> Compose تسجل snapshot state المقروءة أثناء composition. تغيير observable value يعمل invalidation للscopes اللي قرأتها؛ mutation داخل List عادية لا تُرى. stability تساعد skipping فقط لو contract صادقة، ولا تعالج work غالية داخل composition.</p>

<p dir="rtl" lang="ar"><strong>إيه اللي لازم يظهر في إجابتك؟</strong> حدّد الـowner، امشِ في الـexecution order، سمّي الـfailure اللي السؤال كاشفها، وبعدها اربط القرار بـtrade-off واختبار يثبت السلوك.</p>

## القرار العملي

<p dir="rtl" lang="ar">بالنسبة لـState hoisting: hoist لأقل common owner، انشر snapshots جديدة، شيل work من composition، ومتضفش @Stable إلا لما contract فعلًا مستوفاة والtrace تثبت bottleneck.</p>

## الـfailure والـwrong answer

**Common wrong answer:** “Annotate the model @Stable and make recomposition count zero.”

<p dir="rtl" lang="ar">في <strong>State hoisting</strong> المشكلة في الإجابة دي إنها تكسر الـinvariant الأساسية: Compose تقرأ observable immutable state، owner واحدة تستقبل events، وأي stability contract صادق عن كل observable field. النتيجة ممكن تبان سليمة في الـhappy path، وبعد race أوrecreation أوfailure boundary تظهر المشكلة الحقيقية.</p>

## الـtrade-off

<p dir="rtl" lang="ar">في State hoisting: recomposition رخيصة وصحيحة قد لا تحتاج إصلاح؛ derivedStateOf/memoization لهم overhead ويستخدموا بقياس.</p>

## الاختبار اللي يثبت الإجابة

<p dir="rtl" lang="ar">لاختبار State hoisting: غيّر كل field وحدها، أعد ترتيب list، وراقب UI output/recomposition/layout؛ اثبت إن update لا تختفي وإن expensive work انخفضت على release build.</p>
