# UI-Q019 — Complete model answer

## الإجابة المختصرة

**Spoken answer:** “A deep link must build an authorized valid stack and preserve Back behavior.”

<p dir="rtl" lang="ar"><strong>الخلاصة بالمصري:</strong> أي external Intent أو PendingIntent input غير موثوق لحد validation والauthorization داخل الـcomponent، والـidentity والmutability لازم يكونوا مقصودين.</p>

## افهم السؤال قبل ما تجاوب

<p dir="rtl" lang="ar"><strong>المحاور بيديك الحالة دي:</strong> <bdi dir="ltr">A deep link targets an authenticated order while the user is signed out. Build the validation, authentication, authorization, and restored navigation flow.</bdi></p>

<p dir="rtl" lang="ar"><strong>تحت الغطا في Deep-link entry:</strong> الـIntent مجرد رسالة فيها action وdata وextras، والـintent filter يعمل routing فقط. هو لا يثبت هوية المرسل ولا authorization. PendingIntent تضيف تفويضًا من creator لكن identity وrequestCode وmutability يحددوا هل pending intents هتتبدل أوتتعدل.</p>

<p dir="rtl" lang="ar"><strong>إيه اللي لازم يظهر في إجابتك؟</strong> حدّد الـowner، امشِ في الـexecution order، سمّي الـfailure اللي السؤال كاشفها، وبعدها اربط القرار بـtrade-off واختبار يثبت السلوك.</p>

## القرار العملي

<p dir="rtl" lang="ar">بالنسبة لـDeep-link entry: حوّل الـIntent إلى typed command بعد فحص action وscheme/host/path والsizes، أعد authorization للحساب الحالي، واستخدم explicit immutable PendingIntent إلا لو fill-in field موثقة مطلوبة.</p>

## الـfailure والـwrong answer

**Common wrong answer:** “Android matched the intent filter, so the input is trusted and already authorized.”

<p dir="rtl" lang="ar">في <strong>Deep-link entry</strong> المشكلة في الإجابة دي إنها تكسر الـinvariant الأساسية: أي external Intent أو PendingIntent input غير موثوق لحد validation والauthorization داخل الـcomponent، والـidentity والmutability لازم يكونوا مقصودين. النتيجة ممكن تبان سليمة في الـhappy path، وبعد race أوrecreation أوfailure boundary تظهر المشكلة الحقيقية.</p>

## الـtrade-off

<p dir="rtl" lang="ar">في Deep-link entry: استخدم non-exported proxy أو verified App Link لو callers الخارجيين محدودين؛ ده يقلل surface بدل توسيع intent filter.</p>

## الاختبار اللي يثبت الإجابة

<p dir="rtl" lang="ar">لاختبار Deep-link entry: أرسل lookalike host وduplicate params وoversized extras وwrong account وreplayed PendingIntent، واثبت إن الرفض يحصل قبل أي data access أو side effect.</p>
