## Editorial style and terminology

Use professional spoken Egyptian Arabic, preserve established English technical names, and open answers with the actual mechanism or decision. A quick answer should work aloud immediately; the best answer adds a practical scenario and a limit; the deep answer can explain implementation details and recovery. Explanation fields should teach, not duplicate the spoken answer. Avoid unsupported guarantees and invented incidents. The central [terminology policy](ARABIC_TECH_TERMINOLOGY.md) includes accepted English terms and natural Arabic exceptions.

## Technical corrections

- **PAT-01:** Distinguished system-level macro architecture (Clean Architecture/UDF) from localized micro design patterns (Adapter, Strategy, Factory). Removed claims that using design patterns automatically guarantees testability or replaces architecture.
- **MOD-01:** Defined modularization as physical Gradle build and ownership boundaries rather than simple folders. Clarified parallel compilation benefits, Remote Build Cache acceleration, and documented costs of configuration overhead, version catalogs, and inter-module navigation contracts.
- **SYS-01:** Established the 45-minute mobile system design framework: 5-minute scope bounding, non-functional requirements (Offline-first, battery, low-end device RAM budgets), and Unidirectional Data Flow before selecting libraries or implementation details.
- **SOL-01:** Replaced grand classloader/GC claims with behavioral contract substitution and change pressure; provided a concrete checkout payment adapter scenario.
- **SEC-01:** Clarified UID sandbox and SELinux isolation boundaries, distinguishing local on-device protections from server-side authorization authority.
- **PAY-01:** Formulated the six payment state machine transitions with explicit Unknown outcome handling on network timeout and provider status inquiry.
- **SYS-24:** Formulated resilient offline design with local single source of truth, persistent outbox with WorkManager, WAL journaling realities, and conflict resolution contracts.
- **COM-28:** Formulated the fast-input/slow-result rule for derivedStateOf, distinguishing calculation overhead from recomposition skipping.
- **BG-18:** Removed promises of guaranteed client delivery; formulated durable outbox persistence, WorkManager background scheduling, and server-side idempotency.
- **LEAD-12:** Replaced fabricated incident claims with a truthful incident response framework covering blast radius, blameless postmortem, and concrete automated regression prevention.
- **COR-01 to COR-08:** Replaced academic terms (الموزعات -> Dispatchers, التزامن المهيكل -> Structured Concurrency) and formal phrasing with natural Egyptian spoken answers covering user-space suspension, Continuation state machine, CoroutineContext/Job hierarchy, cooperative cancellation, and main-safety at blocking boundaries.
- **KOT-01:** Removed zero-overhead and no-NPE promises. The source now distinguishes Kotlin/JVM class files, Android DEX, Java platform types, and compile-time versus runtime checks. Its JVM fence was made self-contained after the Kotlin suite caught an undefined SDK reference.
- **KOT-14:** Corrected star-projection write claims: `MutableList<*>` does not accept an arbitrary element. The answer distinguishes declaration-site and use-site variance and does not present generics as a complete runtime type check.
- **COR-27:** Removed promises that a local Room record, a key, or WorkManager eliminates duplicate charges. The answer requires a backend idempotency contract with key retention, payload matching, and a supported status path. `withTimeout` does not undo remote work.
- **PAY-12:** Removed automatic ISO reversal, automatic receipt printing, boot-broadcast dependency, and the claim that issuer approval means captured or settled funds. Recovery uses provider-specific status inquiry and later reconciliation; unresolved results remain Unknown.
- **AND-01:** Corrected the four platform component types versus Jetpack Fragment, Service main-thread execution, receiver time limits, and the false implication that a Foreground Service guarantees process survival. The English source and Arabic fields now agree.
- **FLO-01:** Corrected “every Flow is Cold,” one-to-many cardinality as an absolute rule, unconditional `emit` backpressure, and instant cancellation claims. Distinguished `flow {}` from hot `StateFlow`/`SharedFlow` and documented buffer boundaries. The English source and Arabic fields now agree.
- **COM-15:** Removed claims that unstable parameters force full-screen recomposition every frame and that `@Immutable` guarantees performance. The page now states the versioned Strong Skipping rule, equality versus identity comparisons, and the stale-UI risk of false annotations.
- **SEC-02:** Removed claims that all Keystore keys are hardware-backed or immune to a compromised app. The page now requires inspection of the generated key’s security level, makes StrongBox availability conditional, and describes backend authorization and key-loss recovery.
- **BG-01:** Replaced unconditional WorkManager success and timing claims, the idea that every coroutine belongs to a screen, and an overly absolute alarm rule with task-lifetime and policy-based guidance.
- **DI-01:** Removed claims that DI requires interfaces, guarantees testability or lifecycle safety, or automatically enforces Dependency Inversion; distinguished manual wiring from Hilt graph management and semantic binding checks. Its Kotlin/JVM example now compiles and runs in the suite.
- **DAT-01:** Corrected automatic JSON conversion and cache claims, distinguished Retrofit service declarations from OkHttp transport and Repository mapping, and documented cancellation, secret logging, and unsafe write retries.
- **ARC-01:** Replaced a misleading client-side transfer approval implementation with a runnable JVM pricing-boundary example. Distinguished the original Clean Architecture dependency rule from Android’s optional domain-layer diagram and removed guarantees about DTO changes never affecting UI.
- **MEM-01:** Removed fixed heap ranges, near-zero GC pause promises, and simplified bitmap allocation claims. The answer separates managed reachability, native or graphics footprint, allocation churn, and process death.
- **TST-01:** Removed the false five-tier hierarchy, fixed time and test-ratio claims, and untestable pseudo-code. The answer separates scope, execution environment, and UI subject, with explicit limits of fakes and sandbox tests.
- **TST-04:** Replaced incorrect JVM bytecode claims, mandatory-interface and 100-percent-testability promises, and immediate `StandardTestDispatcher` execution. The new order-expiry snippet compiles and passes a fixed-clock boundary test; the answer separates fake-based policy tests from real-adapter tests.
- **BLD-01:** Removed automatic dependency lockfile, unconditional BuildConfig/R8, and KSP-as-kotlinc claims. The answer traces Gradle, AGP, and Kotlin roles with version-aware failure triage.
- **CIC-01:** Removed mandatory internal-track/manual-gate and immediate 100-percent deployment claims, invalid example workflow, and universal flag or rollback promises. The answer distinguishes production promotion from store review and device adoption.
- **DSA-01:** Removed fixed frame and heap numbers, guaranteed sub-millisecond hash performance, Int-overflow-prone examples, and zero-OOM promises. The new two-sum snippet compiles and runs in the JVM suite; answers distinguish expected hash time, auxiliary space, and device measurement.
- **LEAD-01:** Removed fabricated Hilt/Koin timing and safety measurements and unsupported universal architecture claims. The answer uses an explicitly hypothetical offline catalog with a fair alternative, accepted cost, and concrete revisit trigger.
- **SEC-11 reference maintenance:** Replaced a confirmed 404 OWASP MASVS-STORAGE URL with the current primary control page. SEC-11 content is not marked as a completed editorial review.
