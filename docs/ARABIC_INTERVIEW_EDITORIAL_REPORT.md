## Editorial style and terminology

Use professional spoken Egyptian Arabic, preserve established English technical names, and open answers with the actual mechanism or decision. A quick answer should work aloud immediately; the best answer adds a practical scenario and a limit; the deep answer can explain implementation details and recovery. Explanation fields should teach, not duplicate the spoken answer. Avoid unsupported guarantees and invented incidents. The central [terminology policy](ARABIC_TECH_TERMINOLOGY.md) includes accepted English terms and natural Arabic exceptions.

## Technical corrections

- **KOT-01:** Removed zero-overhead and no-NPE promises. The source now distinguishes Kotlin/JVM class files, Android DEX, Java platform types, and compile-time versus runtime checks. Its JVM fence was made self-contained after the Kotlin suite caught an undefined SDK reference.
- **KOT-14:** Corrected star-projection write claims: `MutableList<*>` does not accept an arbitrary element. The answer distinguishes declaration-site and use-site variance and does not present generics as a complete runtime type check.
- **COR-27:** Removed promises that a local Room record, a key, or WorkManager eliminates duplicate charges. The answer requires a backend idempotency contract with key retention, payload matching, and a supported status path. `withTimeout` does not undo remote work.
- **PAY-12:** Removed automatic ISO reversal, automatic receipt printing, boot-broadcast dependency, and the claim that issuer approval means captured or settled funds. Recovery uses provider-specific status inquiry and later reconciliation; unresolved results remain Unknown.
- **SEC-11 reference maintenance:** Replaced a confirmed 404 OWASP MASVS-STORAGE URL with the current primary control page. SEC-11 content is not marked as a completed editorial review.

Primary references were checked for these corrections: [Kotlin Java interop](https://kotlinlang.org/docs/java-interop.html), [Kotlin generics](https://kotlinlang.org/docs/generics.html), [Stripe idempotency](https://docs.stripe.com/api/idempotent_requests), [Adyen POS status](https://docs.adyen.com/point-of-sale/basic-tapi-integration/verify-transaction-status/), and [Adyen capture](https://docs.adyen.com/point-of-sale/capturing-payments/). Provider documents are examples of specific contracts, not universal payment rules.

## Generation and quality gates

The canonical English question bank and IDs were not edited. Arabic content lives in `scripts/elevations/data/arabic_lab_metadata.json`; English and Arabic technical sources live in `Interview-Lab/questions/`. The generator now uses more natural topic guides, topic names, and section labels. The bilingual validator and the affected browser expectation were updated to match those generated headings. The generator still regenerates 485 Arabic and 485 English question pages through `pnpm sync`.

`reports/arabic-editorial-checkpoint.json` records all 485 IDs as `complete`, `legacy_spoken_pass`, or `pending`; completed entries include reviewed fields and content hashes. `scripts/audit_arabic_editorial.py` identifies missing fields, placeholders, untranslated technical labels, academic wording, absolute-claim phrases, answer length problems, exact duplicate answers, broken code fences, and stale completed hashes. It deliberately reports signals rather than promoting a question to complete.
