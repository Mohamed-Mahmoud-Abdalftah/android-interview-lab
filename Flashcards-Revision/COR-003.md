# COR-003 revision cards

1. **Cooperative cancellation checkpoints:** A suspend modifier does not insert cancellation checks into ordinary CPU instructions. I add ensureActive at a measured batch boundary or yield when fairness is needed, then test how much work completes after cancellation.
2. **CancellationException handling:** CancellationException is an Exception. Mapping it to a normal failure can continue retries or publish stale state after the owner is gone. I rethrow it before mapping expected domain or transport failures.
3. **finally and NonCancellable:** NonCancellable around the upload defeats the owner's cancellation and can delay shutdown. I keep the upload cancellable and reserve NonCancellable for a short bounded cleanup such as closing or recording a local terminal marker.
4. **Timeout ownership:** Each timeout represents a different contract. The HTTP client owns transport timeouts, the repository owns operation policy, and the UI may own a shorter patience window. I preserve the cause so timeout, cancellation, and unknown server outcome remain distinguishable.
5. **Cancellation verification:** I use runTest, gates such as CompletableDeferred, start the child, advance the scheduler to the known suspension point, cancel the parent, and assert cancellation plus exactly-once cleanup and no later publication.
