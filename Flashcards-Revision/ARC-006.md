# ARC-006 revision cards

1. **Architecture review order:** Trace input, state owner, side effects, failures, and observability before discussing naming.
2. **Review severity:** A blocker protects correctness or security; a suggestion improves maintainability without pretending urgency.
3. **Repository conflict review:** Offline writes need durable identity, ordering, retry, and conflict policy before sync implementation details.
4. **ADR challenge:** Challenge assumptions with evidence and offer a viable alternative plus consequences.
5. **DSA invariant in review:** A code review can verify the invariant on boundaries instead of trusting a familiar-looking algorithm.
