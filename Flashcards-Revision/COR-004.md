# COR-004 revision cards

1. **Cold flow collection:** A cold Flow executes its upstream separately for every collector. I either keep one collector, move the request behind a cache, or share it with stateIn or shareIn in a scope whose lifetime and start policy match the feature.
2. **StateFlow conflation:** StateFlow uses equality-based conflation. If the new value compares equal to the current value, collectors are not notified. State should be immutable and equality must represent every observable field.
3. **SharedFlow replay and buffer:** Best-effort analytics may tolerate dropping with a measured buffer policy. A payment result is durable business state and should be persisted or represented in state, not trusted to an in-memory SharedFlow with no subscriber.
4. **State versus event:** I first ask whether the message must survive recreation and be acknowledged. If it is part of durable UI state, model it with an ID and acknowledgement. A transient effect can use an event stream only when missed delivery is acceptable and ownership is explicit.
5. **Lifecycle collection:** The coroutine may keep collecting while the view is stopped, wasting work or updating a dead view. I use lifecycle-aware collection with the correct owner and keep the producer lifetime separate from a collector lifetime.
