# ARC-005 revision cards

1. **Module boundary:** A useful boundary groups code that changes together and exposes a small stable contract.
2. **Dependency direction:** Features depend on contracts or shared foundations, not on each other's internal implementations.
3. **Public API control:** Internal implementation stays hidden so refactors do not ripple across the graph.
4. **ADR quality:** An ADR records forces, alternatives, decision, consequences, and a revisit trigger.
5. **Build and ownership trade-offs:** More modules can improve isolation and parallelism but add configuration, graph, and API maintenance cost.
