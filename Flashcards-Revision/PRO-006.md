# PRO-006 revision cards

1. **Release gate:** A release requires all blocking correctness and security signals, not a weighted average that can hide one blocker.
2. **Staged rollout:** Increase exposure only after a fixed observation window and comparable health metrics.
3. **Rollback criteria:** Define thresholds and ownership before release so incident pressure does not move the goalposts.
4. **Migration coverage:** Test every supported installed schema to the target and destructive fallback policy explicitly.
5. **Binary-search invariant:** Maintain a search interval that still contains every possible answer and compute midpoint without overflow.
