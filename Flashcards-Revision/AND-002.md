# AND-002 revision cards

1. **Configuration change versus process death:** ViewModel survives a configuration-created owner replacement, but it lives in process memory. Process death removes it; restoration needs saved-state keys and durable data.
2. **Saved-state size and source of truth:** A Bundle is a bounded handoff, not a database. Store identity and lightweight input, then reload canonical data from the source of truth.
3. **Restoration ordering:** Build one state reducer with explicit restoring/loading/content phases. Seed identity from saved state, read local data, and only publish states that the UI can represent honestly.
4. **rememberSaveable boundary:** Use it for small UI state tied to composition restoration. Hoist screen behavior to a state holder and keep durable business data in the data layer.
5. **Restoration test design:** Test reducer persistence separately, then Android recreation with saved state, and a fresh process-style launch that reloads durable cart identity without reusing memory fakes.
